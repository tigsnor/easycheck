# PlateNote 단일 사용자 우선 출시 계획

## 제품 목표

PlateNote의 현재 목표는 여러 연구실이 함께 쓰는 플랫폼이나 완성형 분석 제품이 아닙니다.

우선 **한 명의 연구자가 자신의 휴대전화에서 실험과 96-well plate를 안정적으로 계획하고, 기록하고, 결과를 확인하고, 백업할 수 있는 앱**을 완성합니다.

이 목표가 달성될 때까지 신규 기능의 우선순위는 다음 질문으로 판단합니다.

1. 한 명의 사용자가 실제 실험을 더 정확하고 빠르게 수행할 수 있는가?
2. 앱 종료, 기기 문제 또는 사용자 실수에도 데이터를 복구할 수 있는가?
3. 별도 설명 없이 핵심 흐름을 완료할 수 있는가?
4. 기존 Excel·수기 기록과 결과를 교차 확인할 수 있는가?

위 질문에 직접 기여하지 않는 장기 기능은 뒤로 미룹니다.

## 현재 목표 사용자와 사용 환경

- 사용자: 생명과학 실험을 수행하는 단일 연구자 1명
- 주 기기: 개인 Android 또는 iPhone 1대
- 저장 방식: 로컬 우선
- 네트워크: 오프라인에서도 핵심 기능 사용 가능
- 데이터 이동: JSON 백업과 TSV 내보내기
- 사용 범위: 실험 노트, Plate 설계, 희석·피펫팅 계획, 결과 입력, 기본 분석

초기 알파에서는 기존 연구실 기록을 바로 폐기하지 않고 PlateNote와 병행해 결과를 대조합니다.

## 단일 사용자 버전 완료 기준

다음 조건을 모두 만족하면 단일 사용자 버전을 사용할 수 있는 상태로 판단합니다.

### 설치와 실행

- GitHub Actions에서 품질 검사와 Android/iOS 빌드가 성공합니다.
- 실제 대상 기기에 앱을 설치할 수 있습니다.
- 앱 종료와 기기 재부팅 후에도 정상 실행됩니다.

### 핵심 실험 흐름

- 실험을 생성·검색·수정·복제·삭제할 수 있습니다.
- 실험별 96-well plate를 편집하고 저장할 수 있습니다.
- 그룹, 역할, 농도, 반복 수와 well 부피를 기록할 수 있습니다.
- 희석 series와 직접 stock 희석 master mix를 계산할 수 있습니다.
- 결과를 개별 입력하거나 A-H × 1-12 행렬로 일괄 입력할 수 있습니다.
- Blank 보정, control 정규화, 평균, SD, CV와 농도별 기초 차트를 확인할 수 있습니다.
- 원본 Plate와 분석 결과를 TSV로 내보낼 수 있습니다.

### 데이터 안전

- 저장 도중 실패해도 마지막 정상 데이터가 손상되지 않습니다.
- 전체 데이터를 백업하고 같은 기기 또는 새 설치에서 복원할 수 있습니다.
- 잘못된 백업 파일과 손상된 저장 파일을 감지하고 사용자에게 알립니다.
- 데이터 형식이 변경되어도 기존 사용자 데이터를 migration할 수 있습니다.

### 실제 사용 검증

- 수동 QA 체크리스트를 실제 기기에서 모두 수행합니다.
- 최소 2주 동안 기존 기록과 병행 사용합니다.
- 핵심 흐름을 막는 P0/P1 버그가 없습니다.
- 계산 결과를 기존 Excel 또는 검증된 소프트웨어와 교차 확인합니다.
- 사용자가 개발자 도움 없이 실험 생성부터 백업까지 완료합니다.

## 우선순위 작업 목록

### P0. 실제 기기 알파 QA

1. 최신 GitHub Actions 세 작업의 성공 여부를 확인합니다.
2. Android APK artifact를 설치합니다.
3. iOS Simulator를 실행하고 실제 iPhone 배포 경로를 정합니다.
4. 수동 QA 체크리스트 전체를 수행합니다.
5. 화면 잘림, 키보드, 스크롤, 공유 sheet와 Files 접근을 확인합니다.
6. 알파 피드백을 P0/P1/P2로 분류합니다.

### P1. 로컬 데이터 안전성

1. [x] 임시 파일에 저장한 뒤 원본을 교체하는 atomic write를 적용합니다.
2. [x] 저장 전 마지막 정상 파일을 자동 보관합니다.
3. [x] 손상된 JSON을 감지하고 정상 backup에서 자동 복구합니다.
4. [x] 데이터 schema version 1과 legacy migration을 추가합니다.
5. [x] 자동 복구가 발생하면 앱 화면에서 사용자에게 알립니다.
6. [ ] 손상 원본과 backup 정보를 확인하고 복구 방식을 선택할 수 있는 고급 복구 화면을 제공합니다.
7. [x] 전체 백업의 실험·Plate 관계를 복원 전에 검증하고 실패 시 기존 상태로 rollback합니다.
8. [ ] 첨부파일 기능 추가 후 백업에 포함된 파일의 무결성을 검증합니다.
9. [x] 손상·복구·legacy migration을 repository 테스트로 검증합니다.
10. [ ] 실제 기기에서 저장 중 강제 종료와 재실행을 검증합니다.

### P2. 실험 사진과 파일 첨부

1. 카메라와 갤러리에서 사진을 추가합니다.
2. 사진 캡션과 촬영 시간을 저장합니다.
3. 실험별 첨부파일 목록과 삭제 확인을 제공합니다.
4. 백업에 첨부파일을 포함합니다.
5. 저장 공간 사용량과 누락 파일을 확인합니다.

### P3. Plate 템플릿

1. [x] 현재 Plate를 결과값 없이 템플릿으로 저장합니다.
2. [x] 저장된 템플릿을 현재 실험 Plate에 확인 후 적용합니다.
3. [x] 템플릿 관리 화면에서 이름 변경·삭제를 지원합니다. 복제는 필요성이 확인될 때 추가합니다.
4. [x] 새 실험 생성 단계에서 템플릿을 바로 선택합니다.
5. [x] CCK-8 2배 희석 3반복 기본 예시를 제공합니다.

### P4. 결과 파일 가져오기

1. [x] CSV/TSV/TXT 파일 선택과 preview를 추가합니다.
2. [x] Well 좌표와 header를 자동 감지합니다.
3. [x] 결과 단위와 wavelength를 확인한 뒤 적용합니다.
4. [x] 결과 가져오기 source 이름과 import 이력을 보존합니다.
5. [x] 중복 import와 덮어쓰기를 경고하고 적용 전 확인을 받습니다.

### P5. 실험 실행 보조

1. 피펫팅 단계별 체크리스트를 추가합니다.
2. Serial transfer와 단계별 잔여량을 계산합니다.
3. Incubation 타이머와 시작·종료 시간을 기록합니다.
4. Reagent lot, 장비와 담당자 메모를 추가합니다.
5. 실험 완료 후 수정 여부를 명확히 표시합니다.

### P6. 단일 사용자 배포 마무리

1. 앱 이름, 아이콘, bundle/application id를 확정합니다.
2. Android internal testing과 iOS TestFlight 배포를 준비합니다.
3. 버전 업그레이드와 데이터 migration을 실제 기기에서 확인합니다.
4. 개인정보·연구 데이터 처리 안내와 앱 내 도움말을 작성합니다.
5. Crash 수집 방식과 사용자 피드백 전달 경로를 정합니다.

## 나중으로 미루는 장기 기능

다음 기능은 단일 사용자 버전이 실제 실험에서 안정화된 후에만 검토합니다.

- 사용자 계정과 로그인
- Cloud sync
- 여러 사용자 실시간 협업
- 팀·연구실 권한 관리
- 서버 기반 공유
- 여러 기관을 위한 관리 기능
- 구독과 결제
- 고급 dose-response fitting과 IC50 자동화
- 규제 대응 수준의 전자서명과 감사 시스템

단, 데이터 손실 방지에 필요한 로컬 변경 이력과 backup 검증은 장기 기능이 아니라 단일 사용자 필수 범위로 취급합니다.
