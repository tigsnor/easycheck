# 실험연구원 관점의 기능 개선 제안

검토일: 2026-10-23 (한국 시간). 현재 코드와 테스트를 바탕으로, 한 연구자가 오프라인에서 96-well 실험을 설계하고 수행·기록·분석하는 흐름을 검토했습니다. 실제 연구원 인터뷰나 장갑 착용 실기기 검증 결과는 아닙니다. 아래 제안은 구현 완료 항목과 구분하며, 임상·규제 시스템 적합성을 의미하지 않습니다.

## 이번에 구현한 다음 작업: 결과 연속 입력

- Plate 하단 또는 더보기의 `결과 연속 입력`에서 선택한 well부터 시작합니다. 선택이 없으면 A1입니다. 여러 well을 선택했더라도 선택 영역에 한정하지 않고 현재 좌표부터 Plate 끝까지 이동합니다.
- 행 방향은 A1 → A2 → … → A12 → B1, 열 방향은 A1 → B1 → … → H1 → A2입니다. 다음 좌표를 저장 전에 표시합니다. 방향은 입력 중 바꿀 수 있습니다.
- `저장 후 다음 well`은 저장 성공 후에만 이동합니다. H12에서는 `저장 후 마치기`로 종료하며 처음으로 돌아가지 않습니다. 중간에는 `현재 well 저장 후 닫기`를 사용합니다.
- 현재 값·단위만 저장하고 농도·역할·메모·그룹·분석 제외 상태를 유지합니다. 0과 음수, 유한한 과학 표기 숫자를 허용하고 빈 입력·NaN·무한대는 차단합니다. 결과 삭제는 기존 well 편집을 사용합니다.
- 다음 well의 기존 값·단위와 제외 상태를 보여줍니다. 결과가 없는 well에는 직전에 입력한 단위를 기본으로 넣되, 기존에 단위가 저장되어 있으면 그 단위를 우선합니다. 기존 측정값의 단위가 없으면 임의로 채우지 않습니다.
- 빈 well과 제외 well도 이동 순서에 포함됩니다. 자동 건너뛰기로 좌표가 예상과 달라지지 않도록 범위를 안내합니다. 방향 변경으로 이미 저장한 좌표를 다시 만나도 이번 입력 중 저장한 최신 값을 표시합니다.
- 저장 실패 시 현재 좌표와 입력을 유지하며 수정·재시도할 수 있습니다. 저장 중 중복 저장·닫기·뒤로가기를 차단합니다. 미저장 입력을 닫을 때 폐기를 확인하고, 앞서 저장된 결과는 유지합니다. 강제 앱 종료 후 미저장 입력 복구는 아직 지원하지 않습니다.
- 각 저장은 기존 Plate 변경 이력과 실행 취소에 연결되며 완료된 실험에서는 입력 기능을 제공하지 않습니다. 이력 보관은 기존 최근 20건 정책입니다.

## 기존 기능에서 수정할 부분

| 우선순위 | 현재 제약과 실험 상황 | 권장 변경 | 완료 기준 |
|---|---|---|---|
| 최우선 | 결과 가져오기 미리보기가 처음 6개 좌표와 개수 중심이어서 전치·시작 위치 오류를 놓치기 쉬움 | 전체 Plate 매핑, 기존 값→새 값 비교, 빈 셀 처리와 시작 좌표를 적용 전에 표시. 전치는 명시적으로 선택 | 모서리 A1/A12/H1/H12, 일부 행렬, 덮어쓰기·취소를 실제 reader 파일로 검증 |
| 높음 | 같은 결과 단위의 control을 역할 우선순위로 모으므로 여러 약물·용매 조건을 한 Plate에서 비교할 때 기준이 불명확함 | 처리군별 blank/control 지정과 비교 대상 well 표시. 기존 자동 기준도 명확히 표시 | 선택한 reference가 화면·계산·TSV에서 일치하고 기준 누락·0 분모 처리 검증 |
| 높음 | 결과가 기록되지 않은 배치 well과 실험 준비 경고가 있어도 완료 시 검토 흐름이 분산됨 | 완료 전 미입력·제외·단위 혼용 점검 화면과 검토 메모 | 경고에서 해당 좌표로 이동하고 의도적인 미측정 이유를 남길 수 있음 |
| 높음 | 기본정보·자원·단계·메모가 한 상세 화면에 섞임 | 설계/실행/결과 화면 구분. 실행 화면에는 현재 단계와 다음 행동을 우선 표시 | 실험 중 단계 완료·타이머 확인에 필요한 스크롤과 탭 수를 실기기에서 비교 |
| 중간 | 확대 시 헤더가 사라지고 H12로 이동하려면 스크롤이 많음 | 고정 행·열 헤더, 좌표 직접 이동, 선택 영역만 연속 입력하는 선택지 | 큰 글자·좁은 화면에서 좌표와 현재 대상이 일치 |
| 중간 | 단위 직접 입력과 일반 숫자 키보드만으로 다양한 장비 결과를 입력하기 번거로움 | OD450/OD570/RFU/RLU와 최근 단위 선택, 지수 입력 보조 키 | 숫자 표현과 단위만 바꾸며 원본 정밀도 보존 |
| 중간 | Plate 변경 이력이 최근 20건이므로 96개 연속 입력을 모두 장기 추적하기 어려움 | 입력 세션 요약과 well별 변경 전후 비교, 보관 정책·파일 크기 설계 | 중간 실패/재시도 기록이 중복되지 않고 재실행 후에도 비교 가능 |

## 추가하면 유용한 기능

| 우선순위 | 제안 | 실험에서 필요한 이유 | 구현 시 포함할 범위 |
|---|---|---|---|
| 높음 | 원본 reader 파일·현미경 사진 첨부 | 숫자만 남기면 장비 export 설정, 기포·오염 관찰 근거를 다시 찾기 어려움 | 앱 저장소로 원본 복사, 촬영/측정 시각·설명·연결 well, 첨부 포함 백업/복원과 누락 검사 |
| 높음 | 시료/세포 배치 정보 | 세포수만으로는 같은 조건의 재현성을 판단하기 어려움 | 시료 ID, 세포주·passage, 배양/처리 날짜, 배지·시약 lot 연결. 필수 항목은 실험 유형에 맞게 선택 |
| 높음 | 예정 시간과 로컬 알림 | 현재 시작·완료·경과 시간만으로는 배양/반응 종료 시점을 놓칠 수 있음 | 단계별 예정 시간, 동시 타이머, 알림 권한 상태, 백그라운드·재실행 복원. OS별 실제 알림 검증 |
| 중간 | 피펫팅 진행 표시 | 계산된 계획과 실제 분주 완료 상태를 구분하기 어려움 | 채널 방향, 현재 행/열, 단계 완료 체크와 되돌리기. 설계와 실제 수행 기록 분리 |
| 중간 | 결과 QC 지도 | 반복값 편차나 가장자리 패턴을 숫자 표만으로 찾기 어려움 | raw/보정값 heatmap, 반복군 CV·누락 경고, 조건별 기준. 자동 이상치 삭제는 하지 않고 연구자가 제외 사유 기록 |
| 중간 | 백업 상태 확인·복원 점검 | 백업 기능이 있어도 마지막 파일이 언제 만들어졌는지 잊기 쉬움 | 마지막 백업 시각과 이후 변경 여부, 첨부 포함 건수 검증, 주기적인 복원 점검 안내 |
| 후순위 | 반복 측정·IC50 등 고급 분석 | 현재 well당 결과값 하나로는 다중 파장·시간 경과 측정을 표현하기 어려움 | 먼저 측정 차원·단위·생물학적/기술적 반복 구분을 설계하고 모델 적합·reference·내보내기 정책을 정의 |

공유 계정·실시간 협업은 현재의 단일 사용자 오프라인 우선 범위 뒤로 둡니다. 우선 추천 순서는 **전체 가져오기 미리보기 → 조건별 reference 선택 → 원본 파일/사진과 백업 통합 → 실행 단계/알림**입니다. 고급 분석보다 입력 좌표·원본·비교 기준을 확인할 수 있는 기능이 먼저입니다.

## 검증과 남은 확인

자동 테스트는 연속 입력의 0/유한값 검증, 저장 실패·재시도, 중복 저장 차단, 미저장 입력 폐기 확인, 행·열 경계, 마지막 well 종료, 방향 변경 후 최신값, 기존 데이터 보존, 변경 이력·실행 취소, 완료 실험 입력 잠금, 320px·글자 1.6배·키보드 여백을 다룹니다.

실기기에서는 장갑 착용, 한 손 조작, 실제 키보드에서 음수·과학 표기 입력, 스크린리더 좌표 안내, 앱 전환 중 저장, Plate reader 원본 파일별 형식을 확인해야 합니다. 후속 기능은 실험 유형과 장비 파일 사례를 확인한 뒤 범위를 좁혀 구현합니다.
