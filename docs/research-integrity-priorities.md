# 기존 기능 개선 우선순위

2026-10-28 사용성 점검과 실험 절차 점검을 통합했습니다. 데이터의 의미가 바뀌거나 입력을 잃는 문제를 먼저 고치고, 실험 실행·분석의 판단 근거를 강화한 뒤 반복 조작을 줄입니다. 시료/세포 배치·QC 지도 같은 신규 기능보다 아래 기존 기능 개선을 먼저 진행합니다. 실제 기기 QA는 각 작업과 병행합니다.

## 실기기 피드백 우선 작업 (2026-10-30)

사용자가 2026-10-29 실기기 테스트에서 발견한 아래 세 가지를 기존 후속 작업보다 먼저 진행합니다. 순서는 **제목 누락 안내 → 같은 Plate의 여러 세포 종류·농도 → UI 가독성**입니다. 이후 기존 3차의 오시작 취소·재시작 기록 보존으로 돌아갑니다.

| 우선순위 | 문제와 작업 | 완료 기준 | 상태 |
|---|---|---|---|
| P1 | 새 실험 생성 시 제목 누락 안내가 키보드/생성창 뒤에 가림 | 입력란 바로 아래 필수 오류 표시, 제목으로 초점·스크롤 이동, 키보드 위에서 안내 확인, 다른 입력 보존 | 구현·자동 테스트 완료, 실기기 재확인 대기 |
| P2 | 같은 Plate에 여러 세포 종류와 두세 개 이상 세포 농도를 배치해야 함 | well/선택 영역별 세포 종류·농도와 단위를 입력·비교하고 저장·복원; 약물 처리 농도와 구분하며 기존 세포 정보 보존; 분석 조건 분리 | 구현·자동 테스트 완료, 실기기 확인 대기 |
| P3 | 색상 등으로 UI 가독성이 떨어짐 | 주요 화면의 글자/배경 대비, 보조 문구·선택/비활성 상태 점검; 색 외에 텍스트/아이콘으로 구분; 작은 화면·큰 글자 검증 | 공통 테마·well 표시 구현·자동 테스트 완료, 실기기 재확인 대기 |

P2는 한 Plate에 세포 종류와 농도를 하나로 제한하지 않는 요구사항입니다. 아래 구현으로 well/영역별 조건을 지정하며, P3의 공통 테마·well 표시도 아래와 같이 개선합니다. 실제 기기의 가독성 재확인은 계속 병행합니다.

### P1 수정 내용

회귀 테스트 3개를 추가했으며 전체 337개 테스트·정적 분석·포맷 검사를 통과했습니다. 키보드 열림/닫힘, 320px·글자 1.6배에서 오류 위치·초점·입력 보존·공백 거절·수정 후 생성을 검증했습니다.

- 제목 입력란에 `필수 입력`을 표시하고, 빈 값 또는 공백만 있는 상태에서 `생성`을 누르면 `실험 제목을 입력해주세요.`를 입력란 아래에 표시합니다. 생성창 뒤에 가려지는 Snackbar는 사용하지 않습니다.
- 제목으로 초점을 옮기고 상단으로 스크롤합니다. 키보드 높이를 스크롤 영역 바깥에 반영하여 입력란과 오류 안내가 키보드 위에서 보이도록 합니다.
- 오류는 유효한 제목을 입력하면 사라지며, 다시 비우면 표시됩니다. 프로젝트·메모 등 다른 입력과 생성창은 유지되고, 제목 누락 상태에서는 실험이나 Plate를 저장하지 않습니다.
- 데이터/백업 형식은 바꾸지 않습니다. Android/iOS 실제 키보드에서 재확인은 [수동 QA](manual-qa-checklist.md)에 남깁니다.

### P2 수정 내용 (2026-10-30)

회귀 테스트 16개를 추가하고 전체 353개 테스트·정적 분석·포맷 검사를 통과했습니다. 종류·농도·단위별 집계/기준 분리, 파일·템플릿·백업·설계 복제 보존, 일괄 지정/해제·읽기 전용·입력 보호·저장 실패 재시도·작은 화면의 키보드 오류 안내를 검증했습니다.

- well 하나, 행/열 또는 드래그 선택 영역에서 하단 `세포 조건`을 눌러 세포 종류와 세포 농도/파종 수를 지정합니다. 같은 Plate에 HEK293 5,000 cells/well, HEK293 10,000 cells/well, HeLa 5,000 cells/well 등을 각각 배치할 수 있습니다. 조건 개수를 두세 개로 제한하지 않습니다.
- 세포 종류는 직접 입력하며 농도는 선택입니다. `cells/mL`와 `cells/well`을 구분하고 자동 환산하지 않습니다. `1e5` 같은 과학 표기를 허용하며 음수·NaN·무한대를 거부합니다. 농도가 없으면 임의의 숫자나 단위를 채우지 않습니다.
- 같은 Plate의 조건을 불러와 재사용합니다. 여러 조건이 선택되면 일괄 변경임을 안내하며 `세포 조건 해제`는 확인 후 세포 종류·농도만 제거합니다. 약물 농도·그룹·역할·결과·메모·제외 여부는 유지합니다.
- `세포` 보기에서 C1/C2 등 표시 번호와 세포 종류·농도·단위·well 수를 확인합니다. C 번호는 현재 배치의 표시용이며 영구 식별자가 아닙니다. 정확한 조건은 well 상세에서도 확인합니다.
- 기존 노트 전체의 세포수 문구는 보존하며 임의로 well에 배분하지 않습니다. 세포 조건을 추가로 지정해야 분석에서 구분됩니다. 노트 생성·편집 화면에도 이를 안내합니다.
- 반복값, 평균·SD/CV, 차트, 반복 부족 점검과 분석 기준을 세포 종류·농도·단위별로 분리합니다. 명칭은 입력한 표기가 같아야 같은 종류로 묶으며, 대소문자·단위의 자동 통합은 하지 않습니다. 미지정 조건은 지정 조건과 별도로 취급합니다.
- 자동 Blank/Control은 같은 세포 조건·결과 단위에서만 찾습니다. 수동 Control도 같은 세포 조건으로 제한합니다. 세포 미지정 Blank는 배지·용매 조건을 연구자가 확인한 후 공통 기준으로 직접 선택할 수 있습니다. 다른 세포 종류·농도의 Control을 자동으로 빌려오지 않습니다. 기존의 그룹별 수동 기준은 세포 미지정 조건에 유지되며 새 조건으로 자동 복사하지 않습니다.
- 결과가 있는 well의 조건 변경/해제는 기존 측정 후 정정 확인·사유를 거칩니다. 변경 전 조건과 측정값은 이력에 보존하며, 저장 실패 시 기존 Plate 재시도/폐기 흐름을 사용합니다. 확인을 취소하면 적용하지 않습니다. 완료·보관 Plate의 편집 잠금도 유지합니다.
- Plate 파일 v3, 템플릿 파일 v2, 전체 백업 v7로 저장합니다. 이전 형식도 읽으며 세포 조건은 미지정으로 유지합니다. 실험 파일은 v4 그대로입니다. 템플릿·설계 복제는 세포 배치를 보존하되 결과를 초기화합니다. Plate/분석 TSV에 `cell_type`, `cell_density`, `cell_density_unit` 열을 추가합니다.
- 미저장 입력의 앱 종료 후 복구, 이력 최근 20건 한도는 기존 정책과 같습니다. Android/iOS 실제 키보드·장갑 조작과 기존 데이터 업데이트 후 비교는 수동 QA로 확인합니다.

### P3 수정 내용 (2026-10-30)

2026-10-31 사용자 요청으로 후속 색상을 슬레이트·틸로 변경했습니다. 주요 동작은 `#0F766E`, 선택된 탭·필터는 `#CCFBF1`, 본문은 `#1E293B`이며 카드·팝업·하단 시트는 흰색입니다. 배경을 중립색으로 명시해 자동 색조가 섞이지 않도록 하고 Plate·분석·백업의 일반 배경도 공통 테마에 맞췄습니다. 실험군과 결과 상태의 의미를 가진 색상은 유지합니다.

새 테스트 5개와 전체 358개 테스트·정적 분석·포맷 검사를 통과했습니다.

- 밝은 바탕 위에서 약 1.4:1 대비였던 노란 primary 대신 진한 파란색을 버튼·링크·선택·저장 중·그래프 강조에 사용합니다. 기본 배경은 중립색으로, 본문/보조 문구는 진한 회색으로 정리합니다.
- 보조 본문 크기를 12→14px, 작은 라벨은 12px 이상으로 조정합니다. 힌트·입력 오류 색상을 명시하고, 버튼 최소 높이를 48px로 맞춥니다. 비활성 버튼은 읽을 수 있는 회색 글자와 배경으로 표시하되 비활성 동작은 유지합니다.
- 저장된 그룹 색상은 바꾸지 않습니다. well의 실제 표시 배경 위에서 검정/흰색 중 대비가 높은 글자를 사용하고, 선택 테두리도 같은 대비색으로 그립니다. 선택된 well에는 `✓`를 추가해 색과 별개로 선택 상태를 구분합니다. 스크린리더의 선택 상태도 유지합니다.
- Plate 헤더를 중립색으로 바꾸고 완료/정상 표시의 초록색을 진하게 조정합니다. 세포 보기 안내는 읽기 전용 Plate에서도 맞는 설명으로 바꿉니다.
- 테스트에서 주요 테마 조합·저장 상태·대표 그룹 배경의 글자와 선택 테두리 대비 4.5:1 이상, 실제 앱 테마의 320px·글자 1.6배·키보드 상태에서 생성/세포 조건 입력을 확인합니다. 실제 조명 아래의 가독성은 수동 QA에서 확인합니다.
- 데이터/파일/백업 형식과 기록값에는 변경이 없습니다. 실기기에서 낮은 화면 밝기·색각 차이·장갑 조작을 재확인한 뒤 추가 조정합니다. 오시작 취소·재시작 기록 보존은 아래 2026-10-31 후속에서 구현했습니다. 다음 개발은 실제 시각 사후 입력과 단계 생략 사유입니다.

## 1차 수정의 동작

- 개별 well 편집은 농도/결과 단위가 없으면 빈 입력으로 열고 그대로 미지정으로 저장합니다. 신규 값도 단위를 자동 선택하지 않습니다. 예시 단위는 입력 힌트입니다.
- 메모·분석 제외만 변경하면 기존 수치·단위·역할·부피·반복 번호를 보존합니다. 측정값 없이 단위만 저장된 기록도 유지합니다. 기존 빈 역할에 농도가 이미 있던 경우 메모 수정만으로 Treatment로 바꾸지 않습니다. 농도를 처음 입력하는 경우의 Treatment 기본 역할은 유지합니다.
- 단위 변경/비우기는 사용자의 명시적인 입력으로 처리합니다. 기존 측정값 자체를 지우면 그 결과 단위도 지우는 기존 동작은 유지합니다. 농도 값 삭제 시 농도 단위는 입력 내용대로 보관합니다.
- 변경 없는 저장은 쓰기와 새 변경 이력을 만들지 않고 닫습니다. 오류 후 원래 값으로 되돌려 닫는 경우도 같습니다.
- 개별 well 편집의 바깥 터치·드래그 닫기를 차단합니다. 닫기 버튼 또는 시스템 뒤로가기에서 변경이 있으면 `계속 편집 / 입력 버리고 닫기`를 선택합니다. 변경이 없으면 바로 닫습니다.
- 명시적 저장 후 파일 쓰기가 실패하면 기존 Plate 저장 실패 배너와 재시도를 통해 동일한 초안을 다시 저장합니다. 미저장 편집창 자체를 앱 강제 종료 후 복구하는 기능은 이번 범위에 없습니다.
- 시작하지 않은 단계의 완료 체크는 완료 버튼을 누른 시각만 기록하고 `시작 시각 미기록`으로 표시합니다. 소요 시간을 0으로 계산하지 않습니다. 과거 완료 기록에 완료 시각도 없으면 `완료 시각 미기록`으로 표시합니다.

- Android/iOS의 알림 클릭 콜백과 알림으로 앱을 시작한 정보를 연결합니다. 초기화는 공유하여 알림 동기화와 이동 준비가 동시에 시작되어도 콜백 등록이 중복되지 않으며, 앱 시작 알림 정보는 한 번만 소비합니다. 알림 권한을 자동 요청하지 않습니다.
- 기존 알림 형식에서 실험 ID/단계 ID/예정 시각을 검증하고, 이동 직전에 저장소의 최신 노트를 다시 읽습니다. 알림의 제목/내용을 노트 데이터로 저장하지 않으며, 알림 클릭 자체로 단계 시작·완료·정정 기록을 만들지 않습니다. 기존 앱 시작/재진입 시 알림 동기화는 유지합니다.
- 실행 탭을 열어 대상 단계를 맨 위에 강조합니다. 단계가 긴 목록의 끝에 있거나 이미 완료되었어도 해당 기록을 확인할 수 있습니다. 완료된 단계에는 새 실행 버튼을 표시하지 않습니다.
- 다른 노트·Plate·편집창·백업 화면이 열려 있으면 알림 이동을 대기하고 안내합니다. 기존 입력과 저장/폐기 확인을 유지하며, 홈으로 돌아온 뒤 최신 기록을 다시 조회합니다. 조회 도중 다른 편집 화면을 연 경우도 이동을 미룹니다. 백그라운드에서는 이동하지 않고 재진입 후 처리합니다.
- 같은 대상의 알림이 대기 중이거나 이미 열려 있을 때 중복 이동하지 않습니다. 서로 다른 대상은 순서대로 대기합니다. 처리한 알림을 사용자가 나중에 다시 누르면 다시 열 수 있습니다.
- 예정 시각/제목/단계 설정이 달라지거나 단계가 이미 완료되었으면 현재 기록 기준의 안내를 표시합니다. 완료·보관 잠금과 정정 중 상태를 유지합니다. 단계가 없으면 임의의 기본 단계를 만들어 대상처럼 표시하지 않습니다. 실험이 없거나 알림 형식이 잘못되었으면 홈에서 안내합니다.
- 저장소 읽기 실패는 대상을 유지하고 명시적 재시도/닫기를 제공합니다. 알림 이동 초기화 실패도 재시도할 수 있습니다. 화면 종료 후에는 알림 콜백 연결을 해제합니다.
- 실험 파일 v4 / 백업 v6 / 알림 데이터 형식을 유지합니다. 대기열은 현재 앱 메모리에 있으며 여러 대기 항목을 프로세스 종료 후 복구하지 않습니다. OS가 실제 전달한 알림의 클릭은 지원하지만 전달·정시 도착을 보장하지 않습니다.

기존 후속은 **오시작 취소와 재시작 시 기존 실행 기록 보존**이며, 이후 실제 시각 사후 입력과 단계 생략 사유를 연결합니다. 2026-10-30 우선순위 변경에 따라 위 실기기 피드백 P1~P3를 먼저 마무리합니다.
