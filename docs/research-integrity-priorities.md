# 기존 기능 개선 우선순위

2026-10-28 사용성 점검과 실험 절차 점검을 통합했습니다. 데이터의 의미가 바뀌거나 입력을 잃는 문제를 먼저 고치고, 실험 실행·분석의 판단 근거를 강화한 뒤 반복 조작을 줄입니다. 시료/세포 배치·QC 지도 같은 신규 기능보다 아래 기존 기능 개선을 먼저 진행합니다. 실제 기기 QA는 각 작업과 병행합니다.

## 1차 수정의 동작

- 개별 well 편집은 농도/결과 단위가 없으면 빈 입력으로 열고 그대로 미지정으로 저장합니다. 신규 값도 단위를 자동 선택하지 않습니다. 예시 단위는 입력 힌트입니다.
- 메모·분석 제외만 변경하면 기존 수치·단위·역할·부피·반복 번호를 보존합니다. 측정값 없이 단위만 저장된 기록도 유지합니다. 기존 빈 역할에 농도가 이미 있던 경우 메모 수정만으로 Treatment로 바꾸지 않습니다. 농도를 처음 입력하는 경우의 Treatment 기본 역할은 유지합니다.
- 단위 변경/비우기는 사용자의 명시적인 입력으로 처리합니다. 기존 측정값 자체를 지우면 그 결과 단위도 지우는 기존 동작은 유지합니다. 농도 값 삭제 시 농도 단위는 입력 내용대로 보관합니다.
- 변경 없는 저장은 쓰기와 새 변경 이력을 만들지 않고 닫습니다. 오류 후 원래 값으로 되돌려 닫는 경우도 같습니다.
- 개별 well 편집의 바깥 터치·드래그 닫기를 차단합니다. 닫기 버튼 또는 시스템 뒤로가기에서 변경이 있으면 `계속 편집 / 입력 버리고 닫기`를 선택합니다. 변경이 없으면 바로 닫습니다.
- 명시적 저장 후 파일 쓰기가 실패하면 기존 Plate 저장 실패 배너와 재시도를 통해 동일한 초안을 다시 저장합니다. 미저장 편집창 자체를 앱 강제 종료 후 복구하는 기능은 이번 범위에 없습니다.
- 시작하지 않은 단계의 완료 체크는 완료 버튼을 누른 시각만 기록하고 `시작 시각 미기록`으로 표시합니다. 소요 시간을 0으로 계산하지 않습니다. 과거 완료 기록에 완료 시각도 없으면 `완료 시각 미기록`으로 표시합니다.
- 완료 체크를 해제해도 없던 시작 시각은 만들지 않습니다. 원래 시작 기록이 있으면 기존처럼 그 시각을 유지합니다. 단계 변경은 아직 상단 저장이 필요하며 자동 저장 연결은 3차 범위입니다.
- 파일/백업 형식 변경은 없습니다. 새 미기록 상태는 기존 nullable 시각 필드로 저장·복원합니다. 과거 앱이 이미 채워 넣은 시작 시각은 실제 시각인지 구분할 수 없으므로 자동 삭제하지 않습니다.

## 검증 범위

1차 수정은 회귀 테스트 14개를 추가했고, 전체 264개 테스트·정적 분석·포맷 검사를 통과했습니다.

- well의 단위 없음·단위 있음·단위만 있음, 0·음수·고정밀 값, 메모/제외 수정, 명시적 단위 변경/삭제, 신규 입력, 저장 실패 후 재시도.
- 뒤로가기·닫기 확인, 바깥 터치·드래그 차단, 변경 없음·입력 되돌림, 320px·글자 1.6배·키보드 여백.
- 시작 없는 완료의 저장 실패/재시도·재실행·완료 해제와 실제 시작 시 알림 예약, 시작 기록 있는 완료/해제, 파일·새 설치 백업 복원, 과거 시각 미기록 표시.
- 기기별 뒤로가기 제스처·키보드·장갑 조작·알림 실제 수신은 [수동 QA](manual-qa-checklist.md)에서 별도로 확인합니다.

## 2차 중 측정 후 조건 변경 보호 (2026-10-28)

회귀 테스트 16개를 추가했고 전체 280개 테스트·정적 분석·포맷 검사를 통과했습니다. 실제 기기 조작 검증은 수동 QA에 남습니다.

- 저장된 측정값이 있는 well의 그룹 연결/그룹명·화합물, 역할, 농도·단위(그룹 기본 단위 포함), 부피·단위, 반복 번호, 유지되는 측정값의 결과 단위를 바꾸면 `측정 후 조건 정정` 화면을 엽니다. 0·음수·분석 제외 well도 대상입니다.
- 좌표별 변경 전후 조건과 기존/적용 후 측정값을 전체 목록으로 확인하고, 정정 사유를 입력해야 저장합니다. 검토 대상 외의 다른 well도 함께 바뀌면 그 개수를 표시합니다. 새 처리 실험은 새 실험 노트/설계 복사본에서 시작하도록 안내합니다.
- 개별 well 편집, 그룹 지정, 희석 재적용, 과거 이력 복원에 공통 적용합니다. 결과 일괄/연속 입력에서도 기존 측정값의 결과 단위를 바꾸면 동일한 확인을 거칩니다. 같은 조건·단위에서 원값만 바꾸는 입력은 기존 결과 수정/덮어쓰기 흐름을 유지합니다.
- 확인을 취소하면 제안한 변경 전체를 적용하지 않습니다. 일반 편집의 제안 입력은 취소되며, 연속 입력은 현재 입력창을 유지하므로 다시 확인하거나 폐기할 수 있습니다. 정정 사유를 쓴 상태에서 나갈 때는 취소를 다시 확인합니다.
- 저장 실패 후에는 같은 초안과 사유로 재시도하고 이력을 한 번만 남깁니다. 연속 입력도 동일한 실패 초안은 사유를 유지하되, 값을 바꾸거나 창을 닫고 다시 시작하면 검토를 다시 받습니다. 미저장 사유의 앱 강제 종료 후 복구는 지원하지 않습니다.
- `전체 변경 이력`의 항목을 누르면 정정 사유·좌표별 변경 전후·측정값을 읽을 수 있습니다. 변경 직전 Plate 스냅샷도 기존 방식으로 보존합니다. 즉시 실행 취소는 확인한 변경의 되돌리기이므로 사유를 다시 요구하지 않고 원래 정정 이력과 실행 취소 이력을 유지합니다. 과거 이력 복원은 현재 측정 조건과 달라지면 다시 검토합니다.
- 측정값이 하나라도 있는 Plate에는 템플릿 적용을 차단하여 기존 결과가 초기화되는 일을 막습니다. 템플릿은 새 실험 또는 측정 전 Plate에 적용합니다. 메모/제외만 편집하거나, 기존 조건을 유지한 채 측정값을 명시적으로 삭제하는 흐름은 그대로입니다.
- Plate 파일 v2/백업 v5 형식을 유지합니다. 사유와 변경 전후는 기존 이력의 설명에, 원래 Plate는 기존 스냅샷에 저장되어 백업·복원에서도 보존됩니다. 이력의 기존 최근 20건 보관 정책은 그대로이며 영구 감사 기록을 의미하지 않습니다. 장기 보관/입력 세션 이력은 6차 범위입니다.
- 이 단계는 편집 가능한 Plate의 조건 변경 보호입니다. 완료·보관 상태의 후속 개선은 아래와 같습니다.


## 2차 후속: 완료 노트 정정·재검토와 보관 보호 (2026-10-28)

회귀 테스트 17개를 추가했고 전체 297개 테스트·정적 분석·포맷 검사를 통과했습니다. 실제 기기 조작은 수동 QA에 남습니다.

- 완료 노트는 사유를 입력한 뒤 `정정 중` 상태·사유·정정 전 노트를 함께 저장해야 편집을 시작합니다. 취소/빈 사유/저장 실패 시 잠금을 유지하며, 실패한 사유는 같은 화면에서 재시도할 수 있습니다.
- 일반 저장·Plate·첨부 이동으로 다시 잠기지 않습니다. 정정 중 상태는 재실행·백업 복원 후에도 유지됩니다. 결과 탭의 `정정 내용 재검토 후 완료`로 최신 단계와 Plate를 다시 점검해야 완료 상태로 돌아갑니다. 상태 선택으로 점검을 우회하거나 정정 중 보관할 수 없습니다.
- 점검 취소/읽기 실패/완료 저장 실패 시 저장된 상태는 정정 중입니다. 완료 저장 재시도는 메모를 유지하고 중복 완료 이력을 만들지 않습니다. 최초 완료 시각은 유지하고 재검토 시각과 메모는 별도 이력에 남깁니다.
- 정정 시작·정정 내용 저장·재검토 완료 이력에서 변경 전 노트의 제목/메모/단계 시각/자원/첨부 목록을 확인할 수 있습니다. 반복되는 이전 이력은 스냅샷에 중첩하지 않습니다. 과거 기록에 없던 스냅샷·완료 시각은 임의 생성하지 않습니다.
- 완료/보관 노트의 빈 단계 목록을 열 때 기본 단계를 자동 추가하지 않습니다. 정정 중에는 과거 단계 종료 알림을 예약하지 않습니다. 새 실험 수행은 설계 복제본에서 진행합니다.
- 보관 노트는 노트·Plate·첨부 모두 읽기 전용이며, 홈의 Plate 바로가기도 같은 규칙을 따릅니다. 완료 노트는 `노트 보관`으로 잠금 해제 없이 보관합니다. 보관 해제 시 완료 기록이 있으면 완료 상태로 돌아가 잠금을 유지하고, 완료 근거가 없는 기존 보관 노트는 안내 후 초안으로 돌아갑니다.
- 실험 파일 v4 / 백업 v6으로 저장하며 기존 실험 파일 v1~v3·백업 v1~v5도 읽습니다. 이전 앱으로 내리는 사용은 지원하지 않습니다.

## 3차 중 단계 실행 저장·알림 상태 (2026-10-29)

회귀 테스트 17개를 추가했고 전체 314개 테스트·정적 분석·포맷 검사를 통과했습니다. 실제 기기의 조작·알림 수신은 수동 QA에 남습니다.

- `시작하고 저장` / `완료하고 저장`과 전체 단계의 시작·완료 버튼/완료 체크는 해당 단계의 실제 누른 시각·예정 시간·알림 설정을 함께 즉시 저장합니다. 완료 체크만 한 경우 없던 시작 시각은 만들지 않습니다. 단계 완료가 실험 노트 전체의 완료를 의미하지는 않습니다.
- 제목·메모·자원·다른 단계 설정·노트 상태의 미저장 입력은 유지하며 단계 저장에 끼워 넣지 않습니다. 해당 단계가 새로 추가된 단계라면 그 단계도 저장합니다. 저장된 단계가 없는 새 노트는 기본 단계 목록과 함께 첫 실행을 기록합니다. 저장된 초안/계획 상태에서 단계를 시작하면 진행 중으로 바꾸고, 사용자가 별도로 선택한 미저장 상태는 그대로 보존합니다.
- 저장 중 중복 단계 조작과 화면 이탈을 막습니다. 실패 시 단계 변경을 초안으로 유지하고 다른 단계 조작을 막습니다. `단계 저장 재시도`는 처음 누른 시각과 동일한 내용을 저장하고 이력을 중복 생성하지 않습니다. `실패한 단계 변경 취소`는 확인 후 그 조작 직전의 단계로 되돌리며 다른 미저장 입력은 유지합니다. 상단 저장은 실패한 단계 기록을 먼저 재시도한 후 남은 폼 입력을 저장합니다.
- 완료 해제는 확인 후 즉시 저장합니다. 기존 시작 시각을 유지하므로 기존 미래 예정 시각에 대한 알림이 다시 예약될 수 있음을 안내합니다. 오시작 취소·다시 시작·사후 시각 입력과 단계 생략 사유는 아직 후속입니다.
- 단계별로 저장됨/미저장/저장 중/실패와 알림 권한 꺼짐/미지원/예약 확인/한도 대기/동기화 실패/예정 시각 지남을 구분합니다. 미저장 설정이 있으면 알림 상태가 저장된 기록 기준임을 표시합니다.
- 운영체제 예약 목록을 다시 읽어 예상 payload가 일치한 예약만 확인됨으로 표시합니다. 취소 요청 후 이전 예약이 남아 있으면 확인 실패로 표시합니다. 권한은 사용자가 명시적으로 요청하며 예약 확인은 실제 수신·정시 전달 보장이 아닙니다.
- 알림 실패가 이미 저장된 단계 기록을 되돌리지 않습니다. 단계 저장 실패는 기존 알림을 변경하지 않습니다. 정정 중 노트는 계속 정정 중이며 단계 변경 직전 노트 이력을 남기고 알림은 예약하지 않습니다. 완료·보관 노트의 읽기 전용 규칙을 유지합니다.
- 실험 파일 v4 / 백업 v6은 그대로입니다. 실패 초안은 현재 화면의 메모리에 있으며 앱 강제 종료 후 미저장 시각 복구는 지원하지 않습니다. 실제 기기의 전달·집중 모드·절전·키보드·제스처 검증은 수동 QA로 남습니다.

## 3차 후속: 알림에서 실험 단계로 이동 (2026-10-29)

회귀 테스트 20개를 추가했고 전체 334개 테스트·정적 분석·포맷 검사를 통과했습니다. 플랫폼 채널의 클릭/앱 시작 정보와 화면 이동을 자동 검증했으며 실제 기기 알림 클릭·전달은 수동 QA에 남습니다.

- Android/iOS의 알림 클릭 콜백과 알림으로 앱을 시작한 정보를 연결합니다. 초기화는 공유하여 알림 동기화와 이동 준비가 동시에 시작되어도 콜백 등록이 중복되지 않으며, 앱 시작 알림 정보는 한 번만 소비합니다. 알림 권한을 자동 요청하지 않습니다.
- 기존 알림 형식에서 실험 ID/단계 ID/예정 시각을 검증하고, 이동 직전에 저장소의 최신 노트를 다시 읽습니다. 알림의 제목/내용을 노트 데이터로 저장하지 않으며, 알림 클릭 자체로 단계 시작·완료·정정 기록을 만들지 않습니다. 기존 앱 시작/재진입 시 알림 동기화는 유지합니다.

- 다른 노트·Plate·편집창·백업 화면이 열려 있으면 알림 이동을 대기하고 안내합니다. 기존 입력과 저장/폐기 확인을 유지하며, 홈으로 돌아온 뒤 최신 기록을 다시 조회합니다. 조회 도중 다른 편집 화면을 연 경우도 이동을 미룹니다. 백그라운드에서는 이동하지 않고 재진입 후 처리합니다.
- 같은 대상의 알림이 대기 중이거나 이미 열려 있을 때 중복 이동하지 않습니다. 서로 다른 대상은 순서대로 대기합니다. 처리한 알림을 사용자가 나중에 다시 누르면 다시 열 수 있습니다.
